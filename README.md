End-to-end retail demand forecasting system, from synthetic data to a production API. Compares six models and selects the best by MAPE.

---

## Business Problem

Inaccurate demand forecasts lead to overstocking or stockouts. This pipeline gives retail teams a data-driven forecast deployable as an API.

---

## Model Results

30-day forecast horizon, synthetic data generated by `01_generate_data.py` (output committed in `data/raw/`).

| Model | MAE | RMSE | MAPE |
|---|---|---|---|
| **Random Forest** | **51.6** | **70.8** | **4.7%** |
| Linear Trend | 161.6 | 195.1 | 15.1% |
| Moving Average (3-day) | 237.2 | 289.7 | 25.1% |
| Naive | 262.3 | 319.1 | 28.4% |
| Exponential Smoothing | 306.5 | 364.2 | 33.4% |
| Seasonal Naive | 370.3 | 452.7 | 39.4% |

**Known issue: the Random Forest score is inflated by data leakage.** In `src/preprocessor.py`, the rolling mean, std, min and max features are computed on `sales` without `.shift(1)`, so each row's features include that day's own sales. The model also sees true lagged sales during the test period, while the naive and smoothing models forecast 30 days ahead blind. The 4.7% MAPE is therefore not a fair comparison. Fix: shift sales by one day before every rolling window and re-run `02_preprocess_data.py` and `04_train_models.py`.

Exponential Smoothing also does worse than the naive baseline here, which is worth investigating.

## Quickstart

```bash
git clone https://github.com/deepanshu0110/retail-sales-forecasting.git
cd retail-sales-forecasting
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python 01_generate_data.py
python 02_preprocess_data.py
python 03_run_eda.py
python 04_train_models.py
python 05_deployment_api.py
```

## API Usage

```bash
curl -X POST http://localhost:5000/forecast -H 'Content-Type: application/json' -d '{"store_id": 1, "days_ahead": 7, "model": "best"}'
```

The API is a Flask app on port 5000. Other endpoints: `GET /health`, `GET /models`, `POST /batch_forecast`.

**Known issue: the Random Forest API forecast is flat.** `generate_model_forecast` repeats the last observed feature row for every future day, so all days get the same prediction. A proper multi-day forecast needs to build each future day's calendar features and roll the lag features forward. If a requested model name is not found, the API falls back to a seasonal average with random noise.
